VGFlow UAT Runtime Bug Root Cause Postmortem

Scope: repo, git log, CHANGELOG, tests, commands, validators, and dogfood notes inspected on 2026-05-24. All percentages are estimates unless marked otherwise.

1. Executive Summary

The recurring pattern is a pipeline mismatch: VGFlow proves static structure, backend recipes, sampled UI flows, and review evidence, but it still does not guarantee that every mutation form is submitted through the frontend to the real backend with assertions on HTTP status, user feedback, redirect, option-loading XHR, and follow-up state before human UAT. The frequency ranking below is inferred from the operator report plus B106 and issue #197 dogfood notes, not from a complete UAT defect dataset [UNVERIFIED frequency] (tests/test_batch106_fe_form_submit_gates.py:3-21, CHANGELOG.md:477-505).

  1. 4xx/422 swallowed after submit: no guaranteed response status assertion or visible error path.
  2. Missing success feedback: toast/status text can be absent while tests pass.
  3. Broken post-submit redirect: navigation is not consistently asserted.
  4. Empty dropdowns/options: failed option XHRs are not first-class assertions.
  5. Role-conditional fields and FE-BE shape drift: multi-actor and response envelope mismatches still reach late runtime checks.

3. Highest-Impact Fix Recommendations

1. Finish B106 and make the static submit-coverage gate blocking

ROI rank 1 Expected UAT bug catch: 35-45% [UNVERIFIED estimate]. Effort: 1-2 days.

Modify scripts/validators/verify-fe-form-submit-coverage.py:86-106 to read canonical LIFECYCLE-SPECS.json.goals, with a legacy fallback to specs, and fail closed when the lifecycle file exists but neither key is present. Change tests/test_batch106_fe_form_submit_gates.py:246-369 so fixtures use goals, then add one regression test that runs the validator against actual generate() output. Promote the runtime and accept calls from warn-only to block-or-explicit-override by changing commands/vg/_shared/test/runtime.md:671-679 and commands/vg/_shared/accept/gates.md:665-675.

Also fix wiring drift: scripts/vg-orchestrator/__main__.py:3973-4038 and scripts/vg-orchestrator/__main__.py:4042-4171 do not include this validator, while generic dispatch builds paths from the validator stem (scripts/vg-orchestrator/__main__.py:4441-4458). Either add verify-fe-form-submit-coverage to both command lists or create an ID-to-path dispatcher. Finally, mirror the B106 codegen directive from agents/vg-test-codegen/SKILL.md:177-211 into commands/vg/_shared/test/codegen/delegation.md:403-425, which still only contains the generic four-layer text.

2. Add a live frontend submit replay before UAT

ROI rank 2 Expected UAT bug catch: 45-55% [UNVERIFIED estimate]. Effort: 3-5 days.

Static spec scanning is necessary but not sufficient. Convert the B106 step at commands/vg/_shared/test/runtime.md:652-687 into a live Playwright replay for every mutation lifecycle goal, not just a text audit. The runner should load LIFECYCLE-SPECS.json.goals, find create/update/delete steps with network_assertion and success_assertion injected at scripts/generate-lifecycle-specs.py:1775-1795, submit through the UI, assert the matched response status is < 400 or an error alert is visible, assert waitForURL or success status visibility when expected, then perform the existing read-after proof.

Update replay instructions in agents/vg-test-goal-verifier/SKILL.md:108-124 and commands/vg/_shared/test/goal-verification/delegation.md:136-149 so submit/save/create/update/delete actions always wrap a response wait and record failures as hard FAILED evidence. Do not rely on the five-view smoke sample at commands/vg/_shared/test/runtime.md:333-337 for mutation goals.

3. Move schema and FE-BE shape checks from advisory to runtime truth

ROI rank 3 Expected UAT bug catch: 15-25% [UNVERIFIED estimate]. Effort: 2-4 days.

Empty dropdowns and bogus 4xxs often start upstream: OpenAPI is too empty for valid test data and FE code consumes a different response shape than BE returns. Tighten scripts/validators/verify-route-schema-coverage.py:10-19 and commands/vg/_shared/build/close.md:360-379 so changed routes must provide body/query/response schemas even when legacy baselines are grandfathered. For FE-BE shape, promote the B95 validator from warn to block for changed files and add the deferred runtime 1-GET-per-FE-route check described in scripts/validators/verify-fe-be-shape-coherence.py:18-23 and scripts/validators/registry.yaml:1246-1253. The existing PR-E read probe should stop treating every 4xx/5xx as "responding" for option/list endpoints that populate form controls (commands/vg/_shared/build/close.md:716-727).

4. Cross-Check With Explore Findings

Agree - High Confidence

  • Explore A is correct in spirit: no existing shipped gate guarantees full FE form submission against the real backend before human UAT. Build close is static/backend-heavy, test contract verification is GET-focused, smoke is sampled, and UAT is the human runtime checklist (commands/vg/_shared/build/close.md:31-40, commands/vg/_shared/test/runtime.md:73-99, commands/vg/_shared/test/runtime.md:333-337, commands/vg/_shared/accept/uat/interactive.md:32-56).
  • Explore C's top classes match the repo's own B106 dogfood test doc and roam lenses: swallowed 4xx, missing success UI, redirect failure, and network/UI truth mismatch are explicitly named (tests/test_batch106_fe_form_submit_gates.py:3-21, commands/vg/_shared/lens-prompts/lens-form-lifecycle.md:36-42, commands/vg/_shared/lens-prompts/lens-business-coherence.md:43-52).
  • Explore B's historical pattern is confirmed. B90-B95 were a sequence of generator correctness and FE-BE drift fixes after PrintwayV3 issue #197; B95 says F-ROAM-01..06 shipped through build/review/test and were caught only later (CHANGELOG.md:477-505, CHANGELOG.md:535-553, CHANGELOG.md:797-851).

Disagree, Nuance, Or New Patterns

  • Nuance: the repo is not completely blind to mutation evidence. Review and test preflight have gates for no-submit or no-2xx evidence (scripts/validators/verify-matrix-staleness.py:1-19, scripts/validators/verify-runtime-map-crud-depth.py:1-16). The recurring gap is narrower: those gates validate recorded evidence, not every generated FE form test's response status, error UI, success UI, redirect, or dropdown XHR.
  • New pattern: B106 is an attempted fix already in the worktree, but it is not effective yet. The validator reads specs, tests seed specs, and the generator emits goals (scripts/validators/verify-fe-form-submit-coverage.py:86-106, tests/test_batch106_fe_form_submit_gates.py:246-369, scripts/generate-lifecycle-specs.py:2010-2030).
  • New pattern: registry entries do not guarantee execution. The registry lists B106 phases as test and accept, but the orchestrator uses hardcoded COMMAND_VALIDATORS and path stems (scripts/validators/registry.yaml:1222-1231, scripts/vg-orchestrator/__main__.py:3973-4038, scripts/vg-orchestrator/__main__.py:4042-4171, scripts/vg-orchestrator/__main__.py:4441-4458).
  • New pattern: codegen instructions are split. The agent skill has explicit B106 instructions, but the shared delegation prompt still has only the older generic mutation four-layer block, so operators should verify which prompt path is authoritative (agents/vg-test-codegen/SKILL.md:177-211, commands/vg/_shared/test/codegen/delegation.md:403-425).
  • Partial disagreement: "negative_specs advisory only" is not universally true. Current delegation says edge cases must be loaded and emitted as variants, but preflight artifact consistency is advisory unless --strict-artifact-consistency is used (commands/vg/_shared/test/codegen/delegation.md:47-58, commands/vg/_shared/test/preflight.md:298-315).
  • New upstream cause: route schema coverage remains a source of noisy 4xxs and empty form data because the repo documents a 99% schema gap that leaves OpenAPI mostly empty (scripts/validators/verify-route-schema-coverage.py:10-19, scripts/validators/registry.yaml:1191-1198).
